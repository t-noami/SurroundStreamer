SurroundStreamer / Linux backend note

Linux実装イメージと検証方法

このドキュメントは、現在の feature/linux-audio-backend ブランチに入っている Linux Audio Input 実験実装の構成、FFmpeg パッケージ、実機検証の進め方を日本語でまとめたものです。

現在の位置づけ

Linux版は「実験実装済み、実機検証前」です。File source は既存の共通処理で動く見込みですが、Audio Input はターゲットLinuxデスクトップ上での確認が必要です。
実装済み Linux backend selector、PipeWire/PulseAudio source列挙、ALSA fallback、Linux x64 FFmpeg生成workflow。
未検証 実Linux環境でのデバイス列挙、Audio Input stream、monitor、Icecast到達、長時間安定性。
未対応 App Audio capture、ネイティブ低遅延monitor、Linux出力デバイスのbackend側列挙。

macOS版と似ている点・違う点

観点 macOS Linux
OSの性格 Unix系。プロセス管理やパッケージングの考え方は近い。 Unix系。ただし配布形式と音声スタックはディストリビューション差が大きい。
音声API Core Audio中心。既存helperはCore Audio専用。 PipeWire、PulseAudio、ALSA。単一APIに寄せにくい。
今回の実装 ネイティブhelperがFloat32 PCMを出す。 FFmpegをLinux capture adapterとして使い、同じFloat32 PCM契約へ合わせる。
将来の本命 Core Audio helper継続。 必要ならPipeWireネイティブhelper化。現時点ではFFmpeg bridgeで検証開始。

実装イメージ

Linuxでは src/main/audio-backends/index.js が process.platform === 'linux' のとき linux-pipewire.js を選びます。

1RendererでAudio Input選択
2Main processがLinux backendへ問い合わせ
3pactl または arecord で列挙
4FFmpegが pulse / alsa をcapture
5Float32 PCMを既存FFmpeg stream graphへ渡す
Audio Input device
  -> Linux backend
  -> FFmpeg pulse/alsa input
  -> stdout: f32le PCM
  -> ffmpeg-manager
  -> Opus / MP3 / Icecast / monitor

共有境界は macOS / Windows と同じく、raw Float32 little-endian PCM とformat metadataです。Linux backendはMP3、Opus、Icecast、downmix、HRTFを実装しません。

Backendの動作

Capability

  • linux-pipewire-pulse: FFmpegとpactlが見つかった場合。
  • linux-alsa: FFmpegとarecordだけが見つかった場合。
  • linux-audio-pending: 必要runtimeが見つからない場合。

デバイス列挙

  • 優先: pactl -f json list sources
  • fallback: pactl list sources
  • 狭いfallback: arecord -l

PCM契約

stdout: raw Float32 little-endian PCM
stderr: newline-delimited JSON

{"event":"format","sampleRate":48000,"channels":2,"bitsPerChannel":32}

Linux用FFmpeg

Linux backendはFFmpegの pulse / alsa input deviceを使います。そのため Linux package には resources/ffmpeg/linux-x64/ffmpeg が必要です。

GitHub ActionsでLinux x64 FFmpegを生成済みです。現在のSHA-256: 6c6354741613366dae965a88882523b7c950e7c6edc8b0c8414ba460d4097877

生成workflow

.github/workflows/build-linux-ffmpeg.yml
scripts/build-linux-ffmpeg.sh

必要機能

  • libopus encoder
  • libmp3lame encoder
  • pulse / alsa input device
  • f32le, Ogg, MP3 muxing
  • WAV, FLAC, Ogg, MP3, MOV/M4A, Matroska/WebM, AIFF/AIF, CAF demuxing
  • headphone, pan, aresample, astats などのaudio filter
  • file, pipe, icecast protocol

検証環境の前提

最初の実機検証は、PipeWire採用の一般的なデスクトップLinuxで行います。

  • Ubuntu 24.04 x64 または同等のPipeWire desktop
  • pactl が使えること
  • PulseAudio compatibility serverが有効であること
  • ALSA fallback検証時は arecord が使えること
  • Icecast test serverへ到達できること
  • 入力デバイスまたは仮想入力デバイスがあること

CLIでの事前確認

アプリ起動前に、Linux上で音声runtimeとFFmpegを確認します。

pactl info
pactl -f json list sources
arecord -l

resources/ffmpeg/linux-x64/ffmpeg -hide_banner -version
resources/ffmpeg/linux-x64/ffmpeg -hide_banner -devices
npm run check:ffmpeg-license:linux

-devices の出力に alsa と pulse が含まれることを確認します。

アプリ検証手順

  1. Linux上で依存関係をインストールし、アプリを起動する。
  2. ログに linux-pipewire-pulse または linux-alsa が出ることを確認する。
  3. File sourceで音声ファイルを選択し、preview、stream、stopを確認する。
  4. Audio Inputタブでデバイス一覧を更新し、sourceが表示されることを確認する。
  5. 2ch入力で短時間streamし、Icecast側で音が届くことを確認する。
  6. monitorを有効化し、preview monitorとstream中monitorを確認する。
  7. 5.1以上の入力デバイスまたは仮想デバイスがある場合、channel countとmappingを確認する。
  8. stop後にFFmpegプロセスが残らないことを確認する。
ps aux | grep -i ffmpeg
tail -n 200 app-log-output

合格基準

項目 合格条件
起動 Linux上でアプリが起動し、backend名がunsupportedではない。
File source ファイル選択、preview、stream、stopが一通り成功する。
Audio Input列挙 pactlまたはALSA由来の入力デバイスがUIに出る。
Audio Input stream format eventが出て、FFmpegへPCMが渡り、Icecastで受信できる。
停止処理 stream停止後に子プロセスが残らない。
ライセンス npm run check:ffmpeg-license:linuxが通る。

リスクと次の判断

  • 現在のFFmpegはLinux共有ライブラリに依存します。AppImage/deb/snapでruntime依存を別途確認します。
  • PipeWire環境でもアプリ側はPulseAudio互換のpulse入力を使っています。
  • 低遅延monitorが必要な場合、FFmpeg bridgeではなくPipeWire native helperを検討します。
  • マルチチャンネルのchannel orderは実デバイス依存です。検証前にmacOSと同等とは扱いません。
  • Linuxを公開release対象にする前に、複数ディストリビューションでFile sourceとAudio Inputの両方を確認します。
