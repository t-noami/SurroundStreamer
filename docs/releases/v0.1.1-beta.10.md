# SurroundStreamer v0.1.1-beta.10

Current cross-platform backend beta build line.

## Local Beta Artifacts

- macOS app: `dist/beta/mac-arm64/SurroundStreamer-beta-0.1.1.app`
- Windows installer target: `SurroundStreamer-beta-0.1.1-setup.exe`

## Supported Beta Scope

- Input sources: Audio Input and File.
- App Audio capture: removed from the supported input-source UI on all platforms.
- macOS Audio Input: Core Audio helper PCM capture.
- Windows Audio Input: native ASIO and MMDevice/WASAPI capture, with DirectShow fallback when the native helper is unavailable.
- Linux Audio Input: not implemented.
- Encoding formats: Ogg Opus over Icecast, Ogg Opus plus stereo MP3, and Stereo MP3 only.
- MP3 destinations: MP3 Icecast and MP3 Shoutcast 1.
- Monitor Output: shared WebAudio path for generic Audio Input paths; Windows ASIO Audio Input and Windows File-source monitoring can use the backend-owned FFmpeg/WASAPI monitor renderer.

## Verification Performed Locally

- `npm run build`
- `npm run build:audio-helper`
- `npm run build:beta:mac`
- `npm run build:mac:dir`

## Windows Release-Preparation Notes

- The main Windows package path is `npm run build:win`, producing `dist/surround-streamer-0.1.1-setup.exe`.
- The Windows helper is packaged as `resources/audio-backend.exe` through `win.extraResources`.
- Local Windows packages are unsigned. Icon embedding is handled separately by the `afterPack`
  `rcedit` hook while `win.signAndEditExecutable` remains disabled.
- The NSIS installer is wizard-based, creates desktop/start-menu shortcuts, and allows changing the
  install directory.

## Remaining Release Blockers

- Windows stable publication still needs signing/SmartScreen planning, broader ASIO device compatibility checks, channel-order documentation, and long-run capture stability tests.
- Linux needs a real Audio Input backend and release validation before public packages are advertised.
- macOS public release artifacts remain ad-hoc signed unless notarization is added.
