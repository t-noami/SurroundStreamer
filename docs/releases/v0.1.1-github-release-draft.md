# SurroundStreamer v0.1.1

SurroundStreamer v0.1.1 is the macOS stable release and the `0.1.1` platform-preparation line for Windows and Linux.

macOS is the supported stable target for this release. Windows is documented as a beta/pre-release path for broader validation. Linux is still preparing and does not have a public artifact yet because Linux Audio Input capture is not implemented.

## Highlights

- Audio Input and File are now the supported input sources.
- App Audio capture has been removed from the supported input-source UI.
- File source supports playback, monitor preview, and streaming.
- File selection includes common audio containers such as WAV, FLAC, Ogg/Opus, M4A/AAC, MP3, AIFF/AIF, and CAF.
- Streaming modes include Ogg Opus over Icecast, Ogg Opus plus stereo MP3, and Stereo MP3 only.
- MP3 destinations include MP3 Icecast and MP3 Shoutcast 1.
- Standard stream channel templates remain Mono, Stereo, Stereo + C, 5.1, and 7.1.
- Monitor Output includes Stereo Pair, Stereo Downmix, and KU100 Near-field HRIR modes.
- Logs, GitHub Repository, and About actions are available from native application menus where applicable.
- Stream startup now shows a loading overlay, validates required fields visually, and reports connection failures in a dialog.

## Platform Status

### macOS Stable

- Supported target: macOS 14.2 or later on Apple Silicon.
- Audio Input capture uses the packaged Core Audio helper.
- File source uses the packaged FFmpeg file-input path.
- Monitor Output uses the shared WebAudio direct monitor path when browser audio-device access is available.
- The bundled FFmpeg binary is a vetted LGPL-compatible macOS Apple Silicon build.

### Windows Beta

The Windows beta path includes:

- Native ASIO Audio Input capture.
- MMDevice/WASAPI Audio Input capture.
- DirectShow fallback when the native helper is unavailable.
- Backend-owned FFmpeg/WASAPI monitor rendering for ASIO Audio Input and File-source monitoring.
- Wizard-based NSIS installer with desktop and Start Menu shortcuts.
- Bundled Windows x64 FFmpeg binary built from FFmpeg 8.1.

For surround Audio Input streaming on Windows, use an ASIO-capable audio interface or ASIO virtual audio device with 6 or more input/output channels. WASAPI/MMDevice endpoints are useful for mono/stereo inputs, but should not be assumed to expose surround capture unless that specific device has been verified.

Windows remains beta/pre-release until signing, SmartScreen planning, broader ASIO device compatibility, channel-order documentation, long-run capture stability, and installer/update policy are complete.

### Linux Preparing

Linux packages are not published for this release. Current Linux work is documentation and packaging preparation only:

- Linux Audio Input capture is not implemented.
- Linux currently falls back to the shared unsupported backend.
- File source behavior is expected to be reusable, but Linux packaging and release validation are not complete.
- A future Linux backend should be PipeWire-first, with PulseAudio or ALSA fallback considered later.

Do not treat a Linux Electron Builder artifact as a supported public release until a Linux audio backend exists and Linux workflows have been smoke-tested.

## FFmpeg And Third-Party Notices

Release packages no longer use the `ffmpeg-static` npm package. They include vetted platform-specific FFmpeg binaries with matching notices and license texts.

The packaged FFmpeg builds include libopus and libmp3lame. AIFF/AIF and CAF support comes from FFmpeg built-in LGPL demuxers and does not add a separate external library license.

- `npm run check:package-licenses -- dist\win-unpacked`

Linux is not release-validated for v0.1.1 and has no public package artifact.

## Known Limitations

- macOS notarization is not included in the current package.
- Windows is beta/pre-release and unsigned.
- Linux Audio Input capture is not implemented, so Linux packages are not published.
- App Audio capture is removed from the supported input-source UI across the current release line.
